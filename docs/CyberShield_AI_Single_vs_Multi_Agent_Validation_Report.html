Single-agent vs multi-agent validation

Both architectures were evaluated on the same 80-question frozen set, with identical Evidence-with-Qwen retrieval evidence and the same deterministic grader.

Retired on 2026-11-18. Finding

Both architectures passed 80/80. In this one frozen-set run, adding a separate Critic did not improve the deterministic gold score. It added 77 Qwen calls and increased investigated P95 latency by 0.82 seconds. Both runs had zero output truncations.

Evidence parity and grading

The comparison utility checked the Evidence-with-Qwen interpretation, structured evidence claims, and retrieved passage IDs, titles and text. All 77 evidence-bearing investigations matched exactly; the two scoped validation responses and one refusal did not collect evidence.

The frozen gold SHA-256 is f82a87f9aa51ee71ac9814345b94824be9d0ffa04b53dd7534bcdcc88b799856. No gold question or expected answer changed.

Grader correction: CS-058’s remediation cites the CISA KEV required action and its evidence ID. The grading rule recognized CISA, CWE, NIST and OWASP as guidance sources but omitted “KEV.” A focused regression now recognizes KEV as the source name. The report’s cited guidance was already present; this corrected source-name coverage rather than changing the answer key.

All seven categories passed after this correction: CVE facts 20/20, CVSS 15/15, KEV 10/10, ATT&CK 10/10, remediation 15/15, multi-step 5/5, adversarial 5/5.

Current architecture

  1. Validate request and run deterministic safety refusal before model or retrieval work.
  2. Evidence with Qwen resolves the current CVE or recent follow-up, prepares a RAG query, checks retrieval relevance and can retry once with a refined query.
  3. Structured NVD/KEV/ATT&CK tools and local RAG assemble the evidence package.
  4. Analyst writes a grounded draft. The multi-agent configuration adds Critic review.
  5. Deterministic final validation checks citations and risk and builds the report.

The one-active-request endpoint rule is preserved; all model calls run sequentially. This 16 November run used at most six Qwen calls per investigation (one evidence interpretation, up to three retrieval reviews, one Analyst draft, one Critic review). The Critic-driven revision loop added on the same day can extend that to a worst case of eight calls: the revision Analyst pass plus the Critic re-review.

Limits of this finding

  • This is one run per architecture on one frozen set; it does not establish repeated-day stability or broad generalization.
  • Independent human review of the gold set, fresh-CVE evidence, operational trace-retention policy and concurrency remain unmeasured.
  • The Critic could still catch qualitative issues not represented by this deterministic grader. This comparison shows no measured score improvement on the current checks.
  • The retrieval reviewer marked CS-058’s retrieved RAG passages insufficient even though its cited CISA KEV required action satisfied the remediation source-attribution rubric. Retrieval relevance should continue to be monitored.

Addendum — 16 November 2026

Secondary LLM-judge benchmark v2.1

The final judge benchmark run completed on 2026-11-16 using prompt version 2.1 in scripts/benchmark_answer_metrics.py: 165 sequential Qwen calls (160 judgments plus 5 calibration controls), 0 errors. Results are in the metric benchmark JSON.

  • Judge pass: single-agent 78/80, multi-agent 78/80, with zero single-vs-multi disagreements across the 160 answers.
  • Calibration: 5/5 deliberately degraded controls detected.
  • The only failures are CS-058 and CS-065 — genuine thin remediation answers where the expected CWE appears only inside the pasted NVD description blob, which the blob-level deterministic grader wrongly passes. These two are the designated human-review sample.
  • A harness bug found during the v2.0 full run was fixed before v2.1: observed cwe_id/cwe_name were extracted from cve_description evidence claims (NVD descriptions never contain CWE strings), forcing mechanical failures on all 30 remediation-category rows. The judge now reads the report’s own summary and remediation texts. Superseded v1 and v2.0 artifacts are retained unedited for the audit trail.
Caveats: the judge uses Qwen/Qwen3-8B, the same model family as the system under test, so correlated bias remains possible. These judge scores are a labelled secondary quality signal; the frozen 80-question deterministic grader remains the only pass/fail authority. ROUGE-L means (single 0.1880, multi 0.1855) and MiniLM cosine means (single 0.5174, multi 0.5157) are descriptive similarities, not pass rates. The 80/80 deterministic scores in these comparison traces come from a newer system version than the 2026-11-11 frozen run that scored 43/80; the two numbers are not comparable without that version reconciliation.

Design note — later changes, not strictly comparable

After these benchmark traces were produced, four design changes landed: D16 NVD reference-first retrieval source; D17 retrieval loop cap raised to 3; D18 Critic-driven revision loop capped at one revision; and D19–D20 deterministic fallback deferred behind the Critic/revision path plus a revision-prompt fix after the EV-0000 placeholder diagnosis. The Analyst system prompt also changed on 2026-11-16. Future runs are therefore expected to differ and are not strictly comparable with the 80/80 traces in this report.
