01

The architectural idea

Separate what must be factual, what must be searched, and what the language model is allowed to decide.

CyberShield AI is a decision-support copilot: given exactly one CVE, it explains severity, known exploitation, affected products, ATT&CK context and remediation—with citations and explicit limitations. It does not exploit systems, execute code or change infrastructure.

Structured facts

NVD and CISA KEV answer precise questions about one vulnerability. These values are parsed by rules, not generated from model memory.

Searchable knowledge

ATT&CK, CWE, OWASP and NIST provide technique descriptions, weakness guidance, practical fixes and formal controls.

Controlled generation

Qwen interprets the evidence question, reviews retrieval, drafts and critiques. Deterministic code owns safety refusal, schemas, CVSS selection, KEV semantics, citations and final risk tier.

Why the one-request API limit does not prevent multi-agent design

“Multi-agent” describes separate responsibilities and state transitions, not simultaneous HTTP requests. At most one Qwen request is active. A typical multi-agent investigation still uses four calls (interpretation, one retrieval review, analyst, critic). The evidence stage can reach four calls (one interpretation plus up to three retrieval reviews), and one Critic-driven revision adds a revision analyst call plus a critic re-review, each critic review retried once when its JSON is unusable — a worst case of ten Qwen calls per investigation. Under the earlier one-retry cap, the retrieval review wanted a refined query in 69 of 80 questions of the 2026-11-16 multi-agent run.

04

Evidence plane: two paths, one evidence package

Specific CVE facts and general security knowledge remain separate until the Evidence Agent assembles the request-scoped package.

Built & verified

Path A — structured CVE investigation

  1. NVD 2.0 lookup: description, vulnerable configurations, dates, CWE references and CVSS.
  2. CVSS rule: select v3.1 → v3.0 → v2; prefer Primary; never mix fields across metric sets.
  3. CISA KEV check: read the local versioned snapshot on every request; never fetch the full feed per question.
  4. Demo date rule: a failed load, undated snapshot or future-dated snapshot produces unknown; dated snapshots at or before investigation time are accepted.
  5. ATT&CK mapping: use only curated/source-backed relationships; otherwise return an empty mapping with a limitation.
Implemented & measured

Path B — hybrid document retrieval

  1. Build a focused query from the CVE context and requested remediation/technique information, augmented with the CVE id.
  2. Run BM25 keyword search and dense semantic search over the same local chunk library; the query and document vectors both come from the course embedding endpoint (18 November 2026, D32).
  3. Take up to 50 candidates from each ranking and combine ranks with Reciprocal Rank Fusion.
  4. Return the top k passages (default 8), including headings, source IDs, URLs and preserved tables.
  5. Convert selected passages into request-scoped Evidence records with stable citation IDs.

Equal rank weighting (alpha=0.5, k=60) merges incompatible score scales. The final results contain usable text and provenance—not just document IDs.

Where every vector comes from · added 18 November 2026 (D32)

One endpoint serves both jobs. app/embeddings.py::EmbeddingsClient is the only producer of vectors in the system: it builds the dense index (scripts/build_index.py), embeds each retrieval query (app/retrieval.py) and supplies the descriptive answer-vs-reference cosine (app/answer_layers.py::cosine, used by scripts/evaluate_batch10.py) — model bge-small-en-v1.5, 384 dimensions, vectors returned already L2-normalised. The local model this replaced is gone: fastembed is no longer in requirements.txt, and there is deliberately no offline fallback, because a local model would embed the query in a different vector space from the stored vectors. Configuration is embeddings_base_url, embeddings_api_key, embeddings_model and embeddings_ca_cert in app/config.py (env EMBEDDINGS_BASE_URL · EMBEDDINGS_API_KEY · EMBEDDINGS_MODEL · EMBEDDINGS_CA_CERT), TLS is verified against vm02-ca.crt in the repository root, and the key stays in the gitignored .env.

Limits measured against the endpoint: at most 16 texts per request, and every input must be under 512 model tokens. There is no silent server-side truncation — an over-long input comes back as HTTP 422 naming its token count — so the client pre-cuts text to 2,200 characters (93.8% of the corpus by character count needs no cut), then re-cuts the few dense passages with the count the server reports, bounded to four passes; 429/500/502/503 retry with backoff, and an unconfigured endpoint or key raises a clear error instead of embedding anything locally. The index build is now about 100 ms per chunk over 10,457 chunks, against the 709 s local-model build recorded before the swap.

Reference-first retrieval · added 16 November 2026 (D16)

The pages each NVD record itself cites are now a first-class retrieval source. scripts/snapshot_nvd_references.py fetched 365 of the 526 http(s) URLs cited in the 57 cached NVD snapshots (69.4%; 43.7 MB in data/raw/nvd_references/ as SHA-256-named files). 161 URLs failed permanently and are recorded with error reasons — 66x403 bot-walls (including all 32 cisa.gov query URLs), 36x425 CDN throttling, 25x404 and ~34 timeouts; 6 ftp:// URLs were skipped. Content is never fabricated for unfetched URLs. scripts/build_reference_chunks.py chunked 315 of the 365 fetched documents into 3,341 chunks covering 34 of the 56 referenced CVEs (50 documents were too short to chunk), stored at data/processed/reference_chunks.jsonl with manifest data/manifests/nvd_reference_chunks.json.

app/retrieval.py adds a ReferenceRetriever: per-CVE-scoped BM25 with Lucene-style smoothed idf, log(1+(N-df+0.5)/(df+0.5)), because classic BM25Okapi idf collapses to 0 on tiny per-CVE candidate sets. The Evidence agent searches the investigated CVE's own reference pages first (query augmented with the CVE id), emits citations with the new source type NVD_REF marked validation_status "retrieved", then falls back to the generic hybrid corpus. CVEs without reference chunks behave exactly as before, and the frozen generic index was not rebuilt, so earlier retrieval benchmarks stay comparable. Limitation: the reference pages are local snapshot copies that may have changed since fetch. Live CS-056 (Log4Shell remediation) now cites 8 NVD_REF official pages first — Apache security page, Siemens PDFs, CISA log4j-affected-db, Intel advisory — where the old run cited only generic CWE+KEV passages.

CISA KEVKnown exploitation and required action; local snapshot.
MITRE ATT&CKEnterprise technique knowledge and verified mappings.

Production-grade document handling: 1,834 documents became 10,457 chunks. NIST tables remain structured Markdown with repeated headers when split; rows are never cut apart. The measured hybrid benchmark reached 82% Recall@5, 83% Recall@10 and 0.655 nDCG@10.

Why NVD records are not embedded: NVD is the structured answer source for the CVE being investigated. Adding the same records to RAG would duplicate evidence, inflate retrieval evaluation and weaken the distinction between lookup and search. The NVD-cited reference pages are different: since 16 November 2026 they live in a separate per-CVE store that is searched first, leaving the generic chunks and index untouched.

Inference boundary

  • Model: Qwen/Qwen3-8B, OpenAI-compatible chat completions.
  • HTTPS verification enabled with vm06-ca.crt; the API key remains in gitignored .env.
  • One active request per key and 60 requests/minute; v1 uses a sequential graph.
  • Endpoint allowance: 8,192 combined tokens and at most 1,024 output tokens; Qwen output is clamped to the remaining combined context budget.

Graceful degradation

  • Missing fact → null plus a limitation; never zero, empty string or “N/A”.
  • Partial tool success → usable cited report with status=partial.
  • Unsafe request → status=refused with a short reason from the deterministic safety gate before workflow execution.
  • Invalid or truncated Analyst draft → an invalid parsed draft is kept (draft_invalid), reviewed and revised once; deterministic evidence-only assembly now applies only to unparseable or truncated output or a revision that still fails validation, is disclosed and keeps status=partial.
  • Unrecoverable tool, review or final-validation failure → status=failed, trace retained for diagnosis.

Latest controlled comparison (16 November): both runs used the same Evidence-with-Qwen stage and identical evidence claims/retrieved passages in 77 investigations. Single-agent scored 80/80 with 300 calls and P50/P95 10.800/15.368 s. Multi-agent scored 80/80 with 377 calls and P50/P95 12.647/16.188 s. Neither run truncated; the Critic added 77 calls without changing the gold score. See the comparison artifact for method and limits. These runs pre-date the same-day D16–D20 changes (reference-first retrieval, the 3-search cap, Critic-driven revision, deferred fallback and the Analyst prompt fix), so runs after them are not strictly comparable with these numbers.

What the user sees while the report is building · added 17 November 2026 (D25)

The UI no longer waits for the finished report. POST /investigate/stream serves one investigation as text/event-stream: a stage opens, every Qwen call inside it reports its size and elapsed time, the stage closes with the facts it produced, and the last event carries the same strict response envelope the non-streaming route returns. Because graph.stream() already yields one state update per node, this visibility needs no extra model call, and the single-active-request rule is untouched — the stream reuses the same lock-serialized investigate() in a worker thread.

What each line is allowed to say. Progress text is generated from the evidence, draft, review and report objects the stage already returned — CVE ID, severity, CVSS, KEV status, record and passage counts, sections written versus left unknown, critic verdicts, citations, risk tier. It is never a model's narration of its own reasoning, and a failed stage names only the exception type so an internal message cannot reach the browser. A refusal emits two events and no agent activity at all, and the guard runs before the stream opens, so a request naming no CVE still gets HTTP 422 JSON rather than an empty event stream.

What was deliberately not done. Token-by-token model streaming was rejected: Evidence, Analyst and Critic parse whole JSON objects and validate them deterministically, so partial text could not satisfy the source-derived check and would hold the one Qwen slot open longer. Instrumentation is a no-op when no consumer is bound, which is why the evaluation runner, the golden-100 job and all 203 offline tests execute the same path and no measured number moved.

Which paragraph justified which citation · added 17 November 2026 (D26)

A citation used to point at a document and nothing more: Citation is a strict, extra="forbid" contract carrying only evidence_id, source and source_url. The paragraph text was always kept — as RetrievedContext records inside the evidence package, written into the JSONL trace — but no route returned it, so a reviewer could not see what retrieval actually contributed to the answer. Rather than widen the frozen report shape and invalidate every baseline keyed on it, the service gained a read-only GET /traces/{request_id} that returns TraceDetail: the retrieval queries, the evidence records, the retrieved contexts, and used_by, which maps each evidence id to the report sections that cite it, computed deterministically from the shipped report’s own citation lists.

Why the source count exceeds the retrieved-passages setting. top_k is the depth of one search, and an investigation searches two pools — the CVE’s own NVD-cited reference pages first, then the generic hybrid corpus, deduplicated by chunk id, across up to three reviewer-gated rounds. Every evidence record then receives exactly one citation id, the structured lookups included. Measured on CS-20261117114516962032 with top_k=8: 20 citations = 16 retrieved passages (8 reference-first + 8 generic) + 4 structured records. This is reported as the contract behaving as designed, not as a defect — but it was invisible until the paragraphs were shown.

What the view then made unavoidable. Attribution is honest about what the report used: in that run 19 of 20 evidence ids are cited by at least one section, all 8 generic CWE passages were retrieved but cited by none, and several top-ranked reference passages are boilerplate rather than advisory content (an Apache log4j page about NUL characters, an Intel.com search-panel navigation block). That is a retrieval-precision finding, and it is left open deliberately: re-ranking would rebuild the frozen generic index that the R0–R3 experiments and the reference-first benchmark compare against. Verification: 211 offline tests (8 new), a live read of 20 evidence / 16 contexts / 1 query for CS-20261117120441239209, and a browser run that printed the chunk id, retrieval score, page title and excerpt beside each citation.

Two measurement honesty fixes · added 17 November 2026 (D27)

The judge was asked to grade grounding on a payload that hid most of the evidence. The golden-100 judge builds its prompt from the report’s citations and the trace’s evidence claims, but the harness sliced that list to 12 citations and 10 claims. Measured over the 100 rows that hid a mean of 7.3 of 19.3 citations on 94 rows and at least one evidence record on every single one, while the prompt asked for a groundedness score about claims the model could not see. The endpoint caps prompt plus output at 8,192 tokens, so the caps had been added as a safety margin — but the largest complete prompt is about 4.5k tokens, barely half the margin assumed. The full pass now sends every citation and every evidence claim; only the truncation-recovery retry stays compact.

The prompt punished correct extra detail and rewarded filler complaints. It capped factual correctness at 2 for "contradicting a reference fact" and required an issues array, which the model filled with self-contradicting lines: of 482 issue strings, 76 assert a contradiction while quoting the same value on both sides ("incorrectly states the CVSS score as 3.1 | 9.0 | CRITICAL, while the reference specifies CVSS 3.1 with a score of 9.0"), 159 object that a fact is absent from the human-compiled reference when the reference is simply narrower than NVD, and 28 turned a KEV snapshot version difference into a factual error. Prompt g100-1.1 now requires any issue to quote the reference phrase it contradicts, states that a fact missing from the reference is not an error, treats a differing catalog version as provenance when listed/not-listed agrees, and allows an empty issues list. The judge cache also keys on the prompt version, so a prompt change can never silently reuse stale verdicts.

The citation view stated an absence it did not know. When the trace read-back failed, streamlit_app.py still printed "no report section cites it" against all 20 citations and "No retrieved paragraphs are stored" — in the reported case because Streamlit had hot-reloaded app/client.py while @st.cache_resource kept a client built from the previous TraceDetail shape, so the response failed validation and the package came back empty. Attribution now comes from a tested citation_attribution() helper that returns "attribution unavailable: the trace could not be read back" and shows the error, and both loopback services run the same contract version. The data was never missing: no stored trace has an empty citation list — the ten investigations recorded on 17 November carry 20 citations over 16 retrieved contexts (one carries 28 over 24 because it refined retrieval twice) and the two oldest records from 11 November carry 12 over 8 — and the trace in the screenshot (CS-20261117122451455487) reads back 20 evidence records, 16 contexts and 19 attributed ids from a fresh process. Verification: 215 offline tests (4 new).

Traces are local JSONL with a Streamlit results table, and that JSONL record stays the system of record. Since 17 November 2026 (D21) each investigation is additionally mirrored to a self-hosted Langfuse v2 that never leaves this machine (docker/langfuse-compose.yml, server 2.95.11, UI/API bound to 127.0.0.1:3100 only, its own Postgres container on no host port, telemetry disabled): one trace per investigation (trace id = request_id), one span per graph node (evidence, analyst, critic, final_validator — analyst and critic each appear twice when the revision loop runs) whose output is that node's result, and one generation per Qwen call carrying the raw system prompt, the raw user prompt and the raw completion, plus model name, token usage, latency and finish_reason, with level ERROR for transport failure, non-200 or a malformed response and WARNING when the output was truncated at the token budget. Export is off unless LANGFUSE_ENABLED=true and both keys are set and the host is loopback — a public Langfuse URL disables export instead of sending data out — and every SDK call is wrapped so tracing can never fail an investigation. Historical runs (the 80-question evaluations, earlier demos, the judge benchmark) were not retroactively traced, so the Langfuse view starts 2026-11-17, and the stack must be started manually before a demo. Since the same date (D24) each trace also carries a deterministic score: deterministic_status (completed / partial / failed, attached by the workflow on both the success and the abort path, with the degradation flags that fired as the comment) on every live trace, and for the golden-100 set deterministic_verdict (PASS / PARTIAL / FAIL / ABORTED) plus deterministic_conflicts, pushed by scripts/push_golden_scores.py under stable score ids so a re-run updates rather than double-counts. The Streamlit report links straight to its trace so a reviewer can read the raw prompt and completion of every Qwen call behind an answer. The LLM judge, ROUGE and cosine are deliberately not written as scores, and no token price was invented, so the cost panel stays at USD $0. No language model writes the gold answer key or acts as the judge.

A 90-second mentor walkthrough

Use this narration while moving down the end-to-end diagram in section 2.

  1. Input: “The user asks one CVE question in Streamlit. FastAPI validates the request before any model or tool work begins.”
  2. Question interpretation: “Evidence with Qwen resolves the CVE or recent follow-up, formulates the RAG query and checks whether retrieved passages help — up to three reviewer-gated searches per investigation, starting with the CVE's own NVD-cited reference pages.”
  3. Evidence: “The Evidence Agent separates exact lookups from document search. NVD and KEV supply facts; the CVE's own NVD-cited reference pages are searched first, and hybrid BM25 with semantic retrieval searches ATT&CK, CWE, OWASP and NIST.”
  4. Generation and review: “The Analyst can only write from this evidence package. The Critic reviews support, completeness and uncertainty, checks citation gaps deterministically, and can send the draft back for one revision when the first review fails.”
  5. Control: “The agents run sequentially, so the system is multi-agent without violating the one-active-request limit.”
  6. Validation: “Code—not the model—calculates risk, validates the schema and ensures every material citation resolves to real evidence.”
  7. Output and proof: “The user receives eight report sections plus limitations and sources. The retrieval benchmark and the 80 integrated gold questions of the frozen 16 November run measured behavior separately — Batch 10 has been the only evaluation set since 18 November — and failure-inclusive traces expose quality and latency without hiding unsuccessful runs.”
“The central design principle is that Qwen coordinates and explains, while trusted sources supply facts and deterministic code enforces the safety, evidence and reporting rules.”
