2. What the system does, in one screen

A user asks a defensive CVE question or follow-up in the browser. The request is validated, then the graph runs Evidence, Analyst, optional Critic and Final Validator. Evidence includes Qwen interpretation/relevance review plus RAG and structured tools; requests run sequentially and can use at most ten Qwen calls (1 evidence interpretation + up to 3 retrieval reviews + analyst + critic, retried once if its JSON is unusable + revision analyst + critic re-review, retried once) when retrieval refinements and one Critic-driven revision are used. Each investigation also mirrors to a loopback-only Langfuse trace (app/observability.py), while the local JSONL record stays the system of record.

No database, no vector database service. Everything is files on this machine: JSONL for records, a vector index file plus a token store for search, JSONL for history. Retrieval is BM25 + dense embeddings + Reciprocal Rank Fusion in app/retrieval.py, with the dense layer reading data/index/embeddings.faiss through app/vector_store.py (added 18 November, D29). That is a FAISS flat index file searched exactly — the ranking rule is unchanged, and searching it is an in-process library call over a local file. There is no vector database server anywhere: no Qdrant, Pinecone or Milvus. What did change on 18 November (D32) is where the vectors come from: no local model runs here any more, and the stored vectors, the vector each query becomes, and the descriptive answer cosine all come from the course embedding endpoint through app/embeddings.py. There is deliberately no offline fallback, because a local model would embed queries in a different vector space from the stored vectors. The one network hop a dense search makes is that call to the course's own service.

6.2 Model and external data access

KindFileFunction in plain English
runtimeapp/qwen.pyThe only place that talks to Qwen3. Sends one chat request over HTTPS with certificate verification and returns the text, finish reason and token counts; raises QwenError on any failure. Each call publishes a live progress event before it starts (model, token budget, estimated prompt size) and one when it returns, carrying the token counts and finish_reason on success or the failure reason on a transport error, non-200 response or malformed body — so the UI can show the model working without a second model call.
runtimeapp/nvd.pyReads the saved NVD JSON and pulls out the parts that matter: the CVSS score and severity, affected vendor and product, CWE candidates, the English description, and which CWE drives remediation advice.
runtimeapp/retrieval.pyHybrid search over the chunk index: BM25 for exact identifiers, dense cosine similarity for meaning, then Reciprocal Rank Fusion to merge the two lists. The dense half embeds the query through app/embeddings.py and then calls into app/vector_store.py, which searches the local FAISS index file — a file on this machine read into memory, not a vector database service. The embedder is a lazy property, so a BM25-only search never opens a connection to the endpoint. A second scorer, ReferenceRetriever, ranks the investigated CVE's own fetched NVD reference chunks with per-CVE-scoped BM25, using a Lucene-style smoothed idf because rank_bm25's BM25Okapi idf collapses to zero on tiny candidate sets.
runtimeapp/embeddings.pyEmbeddingsClient, added 2026-11-18 (D32): the only thing in the project that produces vectors. One endpoint serves both jobs — the dense retrieval vectors (scripts/build_index.py indexes the corpus, app/retrieval.py embeds each query) and the descriptive answer-vs-reference cosine in app/answer_layers.py — so one model defines every vector: bge-small-en-v1.5, 384 dimensions, returned already L2-normalised. The endpoint takes at most 16 texts per request and every input must be under 512 model tokens, which it enforces by rejecting the call with HTTP 422 naming the token count rather than truncating silently; so text is pre-cut to 2,200 characters (93.8% of the 10,457-chunk corpus is untouched by that cut) and anything still over is re-cut with the count the server reports, bounded to four passes. 429/500/502/503 are retried with backoff, and an unconfigured endpoint or key raises a clear error instead of returning a zero vector. TLS is verified against vm02-ca.crt, the key is read only from EMBEDDINGS_API_KEY, and there is deliberately no offline fallback: a local model would embed queries in a different vector space from the stored ones.
runtimeapp/vector_store.pyThe only owner of the dense vectors. write_index() refuses to store anything that is not L2-normalised, because with unit-length vectors the inner product is the cosine similarity. VectorStore.search() asks FAISS for k + 32 candidates, reads those vectors back, rescores them in double precision and sorts by (score descending, row ascending) — which is the exact ordering rule every frozen retrieval benchmark in this project was measured under, so changing the backend did not change any recorded number. Search is exact: no approximate index and no quantisation, so no recall is traded for speed.
runtimeapp/pdf_extract.pyTable-aware PDF text extraction. It keeps NIST compliance tables as real Markdown rows instead of flattening them into unreadable prose, which is what made 2,190 tables and 17,613 rows searchable.

6.3 The five workflow nodes, in execution order

KindFileFunction in plain English
runtimeapp/evidence_qwen.pyInterprets the question and CVE/follow-up, creates a RAG query, reviews retrieval relevance and may request one refined-query retry.
runtimeapp/evidence.pyNode 2, and it makes no model call. Looks up CVE facts, checks KEV inclusion and snapshot freshness, accepts only source-backed ATT&CK mappings, runs retrieval for remediation passages, and gives every item a request-scoped evidence ID. It searches the investigated CVE's own fetched NVD reference pages first (NVD_REF citations, marked retrieved) and then the generic corpus across up to three reviewer-gated rounds.
runtimeapp/analyst.pyWrites one answer synthesis from supplied evidence, then code checks CVSS values, citations and identifiers. Truncated or malformed output uses a deterministic draft. It also builds the CRITIC_REVISION_REQUEST (previous draft, Critic issues, evidence package, exact validation failure) and keeps parsed-but-invalid drafts for review with draft_invalid flags; the system prompt forbids placeholder evidence IDs and requires an empty evidence_ids list in limitations.
runtimeapp/critic.pyOptional separate review of claim support, completeness and uncertainty. It cannot rewrite the draft or pick the risk level; citation findings are re-derived deterministically.
runtimeapp/final_validator.pyNode 5, also no model call. Re-checks draft and review, calculates the risk tier from the frozen rules (KEV + CVSS ≥ 9.0 critical, either one high, CVSS ≥ 7.0 medium, known lower low, otherwise unknown), attaches claim-level evidence IDs, writes visible limitations, and marks the report completed or partial.

6.4 Wiring, serving, history, tracing, scoring

KindFileFunction in plain English
runtimeapp/workflow.pyThe LangGraph wiring: Evidence with Qwen → RAG Evidence → Analyst → Critic → Final Validator. Deterministic safety refusal happens before the workflow; streamed state preserves partial work for tracing. A conditional edge sends a failing review or an invalid draft back to the Analyst once; an unparseable second review reverts to the original draft and first review (revision_review_failed), and deterministic assembly covers unparseable output or a revision that still fails validation. Every node is wrapped in _traced(), which opens a progress stage, publishes what the stage knew going in and what it produced — severities, record and passage counts, sections written versus unknown, critic verdicts, citations, risk tier — and publishes a failure event naming only the exception type when a stage raises.
runtimeapp/service.pyWraps the workflow behind a lock so only one Qwen request is in flight across all callers, which is what the course API requires. Assigns request IDs, enforces the timeout, and merges failed model and stage timings into history rather than losing them. investigate_stream() runs that same locked investigate() unchanged in a worker thread bound to a progress channel, yields each event as it is published, and raises the worker's exception only after the channel closes — so streaming adds visibility without adding a second execution path or a second model call. A refused request emits begin and refused and no agent events at all.
runtimeapp/api.pyBuilds the FastAPI app: POST /investigate returns a strict report envelope, POST /investigate/stream serves the same investigation as text/event-stream so each agent is reported while it works, GET /health answers without touching the model or workflow, GET /history lists saved local traces, and GET /traces/{request_id} reads one stored investigation back — its evidence records, the paragraphs retrieval produced, and used_by attribution computed by _used_by() from the shipped report’s own citation lists — with no model call. The id is matched against CS-\d{4,} before any file is opened, so a traversing id is trace_id_invalid (422) and an unknown id is trace_not_found (404). Both investigate routes call one shared _boundary_detail() guard, so the no-CVE, multi-CVE, prompt-injection and future-CVE refusals return HTTP 422 JSON before any stream opens and before any model call. This is the single public boundary of the product.
runtimeapp/client.pyThe small HTTP client the UI uses to reach the API. It posts the strict request, parses the response back into contracts, and turns network or validation failures into plain messages without leaking implementation details. investigate_stream(request, on_event) reads the event stream instead, handing every progress event to the caller and returning the report from the final event; a stream that ends without one is an error, not a silent success. trace(request_id) reads one stored investigation back and treats HTTP 404 as "there is no such trace here" (it returns None) rather than an error, so the UI degrades to a caption instead of failing an otherwise complete report.
runtimeapp/history.pyAppends and reads the JSONL investigation trace store, so every run — including failures — leaves an inspectable record on disk that the history screen and the evaluator can replay. Recent fields make the fallback path visible: first_draft_invalid, first_draft_invalid_reason, draft_invalid_reason, draft_fallback_reason and revision_review_failed. get(request_id) scans the same file under the same lock and returns one complete record — request, response, evidence, retrieved contexts, model calls and error — which is what makes the citation paragraphs inspectable without a database. Every record also carries a runtime block — embeddings_model, embeddings_dim, dense_backend, chunks_sha256, index_generated_at — read once per process from data/manifests/index.json, falling back to the configured model when that file is absent, so a history row names the index that produced it instead of being mistaken for a retired one.
runtimeapp/answer_layers.pyThe answer-level evaluation layers, with the two authorities kept apart: field_check() compares the fields the gold answer states against the fields the published report states and is the only pass/fail record, while cosine() and judge_one() are descriptive. Since 2026-11-18 (D32) cosine() embeds both sides through app/embeddings.py, and the module states the rule its docstring carries: a cosine measured before that swap, by the local MiniLM model, is a different measurement and the two are never placed in one column or one table.
runtimeapp/answer_metrics.pyThe secondary text measures: ROUGE-1/2/L F1 over case-folded token n-grams, plus the flattening of a report into the text a metric scores. Surface overlap only — it can describe an answer, never decide a verdict.
runtimeapp/observability.pyMirrors each investigation to a self-hosted Langfuse v2 that is bound to loopback only: one trace per run (trace id = request_id), one span per graph node whose output is that node's result, and one generation per Qwen call carrying the raw system prompt, raw user prompt and raw completion with model name, token usage, latency and finish_reason — level ERROR for a transport failure, non-200 or malformed response, WARNING when the output was truncated at the token budget. Export stays off unless LANGFUSE_ENABLED=true, both keys are set and the host is loopback, and every SDK call is wrapped so tracing can never fail an investigation. The JSONL store below remains the system of record. Since D24 it also exposes score() (one deterministic measurement attached to a trace, with an optional stable score id so a batch writer can update instead of duplicate), flush() for scripts that write scores outside a run, and trace_url(), which builds the loopback link to a trace after resolving the project id once and percent-encoding the trace id.
runtimeapp/progress.pyThe live progress bus that lets the UI show agents thinking. ProgressChannel is a thread-safe queue a consumer iterates until a sentinel closes it; bound() and stage() attach a channel and a stage name to the current context with contextvars, and emit() publishes one typed event carrying that stage. With no consumer bound, emit() returns immediately, so the evaluation runner, the golden-set job and every offline test behave exactly as before — which is why adding visibility changed no measured result.
runtimeapp/eval_dashboard.pyThe read-only layer behind the two evaluation dashboards, and the only module in the repository that knows the Excel column vocabulary. It computes nothing: workbook text is joined by test_id and claim_id to the numbers already stored in data/evaluation/golden_100/metrics.csv, retrieval.csv and data/evaluation/batch10_live_20261118/scores.json, retrieved passages and the full Batch 10 answer are read from the run traces (the workbook copy and generated_claim are capped at 1,200 characters while real answers reach 2,444), and an empty cell prints not captured instead of a plausible zero. Retrieval ratios are relabelled, never recalculated; the Batch 10 answer verdict is derived through the same rule as scripts/write_golden_columns.py:verdict() so the dashboard cannot disagree with the column it displays. Every detail view carries the list of paths it read, and the exporters turn a table or a whole CVE into CSV or paste-ready Markdown (pipes escaped, newlines turned into <br>) so a report figure is copied rather than re-typed.

7.3 The NVD reference store and the Batch 10 evaluation (added 16 November, extended 18 November 2026)

KindFileFunction in plain English
buildscripts/snapshot_nvd_references.pyDownloads every http(s) reference URL cited in the 57 cached NVD snapshots into data/raw/nvd_references/, saved once under its SHA-256 name with bytes, tags, citing CVEs and fetch status in a per-URL index. Failures (403 bot-walls, 425 throttles, 404s, timeouts) are recorded with an error class, never fabricated, and a rerun retries only URLs that did not previously succeed.
